# Windows 原生桌面版实施计划

日期：2026-09-14

## 目标与约束

交付可运行、可安装的 Windows 原生 Recappi Mini，与 macOS 已实现功能对齐。整体流程、信息层级、窗口职责、主要布局与交互习惯以 macOS 版为基准；控件视觉可采用 Windows 原生样式，不追求像素复刻。优先低空闲开销、可靠录音和可维护性。

- 使用 C# 原生桌面技术，不使用 Tauri、Electron、WebView 或浏览器 UI。
- 已完成 WinUI 3/WPF 基础探针比较，采用 WPF + C#；依据和测试局限见 [验证记录](windows-native-validation.md)。不得把探针体积当作完整应用开销。
- 复用现有 Windows WASAPI 系统音频、进程音频和麦克风采集代码；保持现有 CLI、macOS 和协议兼容。
- 桌面版运行不依赖用户安装 Node。原有 TS API/录音编排代码作为协议参考，需要共享能力时优先抽取 C# 核心而非再包一层 CLI。
- macOS 的系统专有交互按 Windows 等价行为实现；源码中的未实现占位不冒充已支持功能。
- 本计划和所有验收证据持续更新。截图、演示数据、单元测试和真实后端验证分别标注，不互相替代。
- 2026-09-15 用户进一步明确：外观可以不同，但整体流程、layout、UX 应尽量一致。需逐屏核对原版导航、内容分区、主次操作与状态转换；当前 Windows 的独立本地库/云库入口、长表单设置等不能仅以功能存在视为对齐完成。
- 本次功能分支独立交付；此前 CLI 合并授权不延伸为本次默认分支合并授权。
- 2026-09-15 用户要求 UI 验收录制视频、提取去重关键帧、分析关键 UI 并自动验收。后续 UI 验收必须保留视频、帧时间点和通过/失败/证据不足判定；时间线未覆盖、画面遮挡或采样不足不得判通过。

- [x] 建立功能矩阵：逐项记录 macOS 源码入口、实际能力、Windows 现状、实现位置、验收方式。见 [功能矩阵](windows-native-feature-matrix.md)，已核对相关 UI 测试入口；后续随实现更新。
- [ ] 核对后端契约：认证、上传、转写/摘要作业、实时字幕、库管理、搜索、问答、导出、版本历史。标注占位接口和服务限制，例如 macOS 录音重命名 Save 当前未接入 API。
- [ ] 完成原生窗口实验：托盘、可拖动录音条、独立字幕窗、普通库窗口；验证显示不抢焦点、控件可交互、置顶、关闭隐藏、恢复、DPI 和屏幕边界。
- [ ] 完成最小应用 x64/ARM64 构建和发布；记录 WinUI 3/WPF 选型及依赖、维护成本、窗口能力依据。若候选失败，先记录证据再采用另一原生方案。
- [ ] 记录性能基线：冷启动、托盘空闲 CPU、工作集/私有内存、安装与分发体积；统计全部应用相关进程与运行时依赖，明确测试环境。

阶段出口：功能矩阵可追踪；选定框架的真实窗口可操作、可构建，资源开销有测量依据。

## 阶段 2：录音核心与桌面生命周期

- [ ] 建立原生应用和可测试的共享核心，隔离窗口/ViewModel、录音状态、网络服务和持久化。跨窗口共享一个录音会话，窗口销毁不能结束录音。
- [ ] 支持系统声音、指定进程及子进程、麦克风设备选择与开关；保留设备消失、权限拒绝、不支持进程录音系统版本的明确反馈。
- [ ] 对齐 idle/starting/recording/processing/done/error 状态；防止重复开始、开始未完成即停止、多窗口竞争和退出截断 WAV。
- [ ] 实现计时、录音电平、停止、丢弃确认、本地保存、打开目录；录音中切换麦克风不得破坏时间线。
- [ ] 实现托盘状态、显隐和恢复、单实例、退出录音确认；会话录音与后台处理独立于窗口生命周期。
- [ ] 实现音频活动/会议录音建议、静音或会议结束的停止提醒、隐藏后长录音提醒和时长上限；平台检测能力差异写入矩阵。
- [ ] 验证真实系统音频与麦克风混录、进程隔离、静音时间线、设备中断与停止落盘；运行现有 Windows CLI 回归。

阶段出口：无 Node、无 Web UI，真实录音闭环可用，关闭窗口仍安全录制。

## 阶段 3：账号、云处理和实时字幕

- [ ] 原生首次引导、权限说明和设置入口；支持跳过登录本地录音，云功能按认证状态展示。
- [ ] 对齐现有登录流程、回调、刷新/过期/重连/退出状态；凭据保存在 Windows 受保护存储，不进日志或明文配置。
- [ ] 实现本地会话索引、上传进度、自动/手动转写和摘要、后台处理、状态轮询、失败重试与完成提醒。
- [ ] 实现实时字幕连接、原文、翻译、语言/场景配置、断线重连和失败提示；字幕失败不得中断本地录音，队列必须有界。
- [ ] 实现独立字幕窗展开/紧凑、原文/译文显隐、关闭与重新打开；窗口状态与录音会话一致。
- [ ] 验证离线录音、上传失败保留本地文件、会话过期、字幕断网恢复、后台处理时新建录音；真实服务测试仅使用当前已授权的测试账户和可控样本。

阶段出口：真实录音能上传、生成内容并恢复失败；字幕不影响录音可靠性。

- [ ] 录音列表、加载/空/错误状态、刷新、搜索、选择恢复、当前会议入口、音频文件导入及处理。
- [ ] 摘要与逐字稿、长文档虚拟化、说话人展示/已支持的修改、文字复制、音频播放/跳转/倍速、文字与播放定位联动。
- [ ] 问答输入、流式回答、错误重试、引用跳转；避免切换会议时串用对话或播放状态。

## 阶段 5：质量、轻量化与交付

- [ ] 按 Microsoft Store 主分发渠道完成 MSIX 交付；以 ScreenCam 实际发布脚本、依赖和生命周期门禁为参考，保持 Recappi 的 WPF、无 WebView/Node 约束及 x64/ARM64 范围。详见 [商店发布与体积优化计划](windows-native-store-release.md)。
- [ ] 审计自包含包冗余依赖，逐项验证优化；提交同版本、同架构的优化前后下载字节、安装占用及冷/热启动对比。商店共享依赖、差分下载的收益必须独立实测，不能用 ZIP 大小替代。
- [ ] 在无 SDK、无预装应用运行时和历史 Recappi 数据的干净系统验证安装、首次启动、真实录音/播放/导出、升级保留数据、卸载及重装；保留安装日志、依赖清单、视频和关键帧判定。开发机启动不能替代此门禁。
- [ ] 测试关键状态转换、会话/设备/网络失败、凭据隔离和云契约；加入可重复的原生 UI 冒烟测试。

- [ ] 分别测量托盘空闲、录音、录音加字幕、长逐字稿和关窗后的 CPU/内存；关闭不需要的计时器、动画与窗口，排查持续增长和后台忙轮询。
- [ ] 完成 x64/ARM64 发布产物、干净环境启动验证、运行时依赖说明、安装/卸载与用户数据保留策略；ARM64 编译和 ARM64 实机验证分别记录。
- [ ] 运行受影响的 CLI、原生核心与 macOS 可用检查，确保旧入口兼容。最终整理功能矩阵、验证命令/结果、性能数据和已知限制。

## Goal 完成标准

完成以上实现与可执行验证，交付原生应用产物及可审查变更。仅有计划、空窗口、模拟数据或主流程演示不算完成；未验证或受外部条件阻塞的项目不得勾选。按依赖顺序推进，优先修复录音数据完整性和生命周期问题。
