# Windows 原生版性能测量

## 当前结论

完整 x64 自包含 App 已补充 5 次新进程启动测量：预先配置、未登录、系统声音来源、关闭麦克风/字幕/上传/建议，首帧、设备枚举、账号恢复和开始按钮可用后，中位观察时间 757 ms，范围 747–845 ms。系统文件缓存未清理，不代表重启后的冷缓存、首次引导或云账号连接启动。具体方法和原始数据见下节。

统一录音库的大列表虚拟化已修复。10,000 条已加载录音时，实际创建的列表项为 12–13 个，末条选择和刷新后仍保留可见选择。以下是生产 WPF 窗口处理合成数据的测量，不代表真实云请求、完整 App、ARM64 或录音/字幕场景验收。

- 空闲 CPU 为单核百分比，等待 1 秒后采样约 10 秒。内存仅为测试进程当时工作集/私有内存，包含诊断数据和测试运行时；没有测全部相关进程、峰值、长时间增长或冷启动。

## 发现与修复

第一次诊断在 500 条时发现创建了全部 500 个列表项，立即失败。此前仅设置 `IsVirtualizingWhenGrouping` 并不能证明实际虚拟化，已显式启用内容滚动、虚拟化及容器回收；常规 WPF 回归加入 500 条实际窗口分页、容器数量、末条选择与跨日刷新检查。

分页去重由每条扫描现有列表改为每批构建 ID 集合，避免大列表时重复全表扫描。没有根据单次耗时声称固定性能提升。
